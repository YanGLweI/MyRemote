## 先说清楚：v1.0.5 的 M22 欠了什么

v1.0.5 的说明把 M22 写成"四条判据脚本、回归测试与现场验证均已通过"。2026-09-02 逐条
核对源码、装机镜像与现场日志后，这句话**只有两条成立**，撤回它：

- 监管线程 cancel-first：成立，本机判据全绿。
- `STALE(service stopped)`：成立，本机在真的停在 `STOP_PENDING` 的服务上见到了这一行。
- "bye 排空"：修得弱于约定——等的是队列**出队**，不是**送达**，之后再补一段写死的
  `Sleep(100)`。代理日志仍可能把"宿主走了"记成"管道断了"。
- "权限不够不再说成没装服务"：只修了一半。分岔写在了服务自己的调用路径上，
  `--service-state` 的首行仍把所有失败印成 `not installed`，托盘那枚说明框仍**无条件**
  在尾巴上拼一句"需要管理员权限"——所以一个提权进程点了那三项也会被告知权限不够。
- 还有一条当时就列在 M22 名下、但**根本没做**：F5，让「启用后台服务」这一项自带可供性
  且真办得成。装完 1.0.5/1.0.6 觉得"M22 什么都没改"，看到的正是这一条。

## 这一版修的事（M24：把上面那三条欠账补完）

- **托盘那一项现在自己说清要什么，点了真的办事。** 前台运行且服务停着时，受限令牌下
  读作「启用后台服务（当前：前台运行，开机不自启；需管理员批准）」；提权令牌下不带后缀，
  因为对它来说这就是个开始按钮。点它不再只弹一段说明：提权直接启动服务，受限去要一次
  UAC 批准，批准之后由 SCM 裁决起没起来。你按"否"会得到「已取消，后台服务没有启动」，
  框根本没弹起来会得到带错误码的另一句话——两种失败字面可分，都不会再被说成权限问题。
  启用成功后下一枚菜单就不再给这一项。
- **错误码一路带话。** `--service-state` 的首行分成四种真话：拿不到 SCM、确实没装、
  这个令牌读不到它（`ACCESS_DENIED`）、查询失败（带 `error N`）；即使一句都读不到服务，
  `console session:` / `stations:` / `host:` 照样打印——这时只剩文件龄那条规则能判
  `host.status`，读数本身仍有价值。启动/停止超时也不再被写成权限不足，而是带上最后看到
  的状态（`(last state 3)` 就是 `STOP_PENDING`）。
- **"bye" 等到真的写上管道。** 每个代理各自记账宿主"说了几行"与"写出去几行"，退出时
  所有代理共用一个 2500ms 截止：写完、这扇门已经关了、或那个进程自己走了，三者任一即
  落定。没落定的会留下一条点名警告，告诉你去看哪个 `tray-<会话>.log`、以及那份日志为什么
  会写"管道断开"。写死的 `Sleep(100)` 没有了。
- **一次实测：服务能不能停。** 这台机器上曾有一个服务停在 `STOP_PENDING` 超过半小时、
  `service.log` 在"stop requested"之后再无一行，1.0.7 出一版就为了把"这是不是产品缺陷"
  问清楚。**问清了：不是。** 装机版 1.0.6 上 `sc start`/`sc stop` 往返三趟，全部在 12ms 内
  落定，每趟 `service.log` 都在"stop requested"之后继续写满五行直到
  `MyRemote agent service stopped`。那个卡住的进程属于一个**从未提交的构建**——它的文件名写着
  `1.0.5`，而版本资源里是 `1.0.7`。完整台账（含"1.0.7 自身的停机还没实测、只读到路径有界"
  这条边界）在 `TASKS.md` 的 M24 账里。

> 顺带一提：v1.0.4 修的是托盘三条症状（隐藏不生效、配置窗显示默认值、菜单形状说谎），
> v1.0.3 修的是"托盘菜单点一次就失灵"。历版修复全部沿用。

## 三步跑起来

1. 控制端机器装 Server 并运行。右下角「设置」里把连接密钥换成只有你知道的串（改完要重启控制端）。
2. 被控机器装 Agent：向导里填控制端地址与同一个密钥，保持勾选「安装并启动系统服务」——这是唯一能在**无人登录**时工作的形态。
3. 控制端里双击在线设备 → 输入该设备的控制密码（没设置就留空）→ 查看并操作远程桌面。

批量推送（不需要 WinRM）：

```bat
MyRemote-Agent-v1.0.7-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART ^
  /TASKS=service /SERVERIP=<控制端地址> /SERVERPORT=7500 /SECRETKEY=<与设置里一致的串>
```

三个参数都选填。**实测（v1.0.0）：一个都不给（`/TASKS=`）时装完什么都不写**——退出码 0、目录里没有 `config.json`、机器上正在跑的服务一行没动。之后自己填：开始菜单「MyRemote 被控端 配置界面」、桌面上的「MyRemote 被控端」，或者直接双击 `agent.exe`——前台启动会先弹配置窗，保存后才开始连。静默安装不会弹这个窗。

填了的那几项由 `agent.exe --set-server` 落盘：它按 agent 运行期同一套顺序找到该写的文件（`%ProgramData%\MyRemote\config.json` 优先，其次 exe 旁边那份），先读回来、只覆盖你显式给出的项，所以设备名、控制密码、编码宽度与"显示托盘图标"都不会被一次重推抹掉。**换控制端地址现在重推包就够了**（v1.0.3 及更早：ProgramData 里已有一份时向导填的会被无视，只能改那个文件）。

**卸载**：`unins000.exe /VERYSILENT`。在 YEUNG 上实测：服务摘掉、`agent.exe` 和卸载器自己都不在了，但 `config.json`、`agent.log`、`host.status` 留在原地（`%ProgramData%\MyRemote\` 里的那几份也一并留着）——所以"卸了再装回去"这个最常见的动作不需要重填地址，装回来还是同一台设备。

## 能做什么

- **无人登录也能连**：服务把采集/注入进程投放到真正持有控制台的会话，机器停在登录界面时可以远程查看并远程输入密码登录 Windows；有人用 RDP 抢走控制台时画面自动等回来，隧道不断。
- **画质三档**＝流畅 / 均衡 / 清晰（720p / 1080p / 原画），只改编码大小，不碰对端桌面。**分辨率下拉真的改对端桌面**，只作用于本次会话、不写注册表，对端不支持时显示 `--` 而不是假数据。
- **延迟读数＝一次网络往返**，与画面是否在动无关；老版本 agent 不认这个探测，就显示 `--`。
- 多标签并发（最多 4 路）、设备搜索（名称/IP/设备号/备注）、右键菜单、逐设备备注、事件日志抽屉、记住窗口布局与默认画质。
- 键盘捕获模型：点画面才接管，连按两次 Esc 交还；`Alt+F4` / `Win` / `Alt+Esc` 永远留在本机。
- 传输全程 AES-128-GCM + HKDF + 密钥校验；设备号由 MAC 与机名派生，**卸载重装后还是同一行**，备注继续有效。
- 中文安装向导；控制端安装时加一条**按程序**放行的入站规则（被控端不需要任何放行）。

## 坐在机器前的人：托盘图标

v1.0.1 的图标画在物理控制台会话里，RDP 里永远看不见；v1.0.2 改成每个有人登录的
会话（控制台、RDP 都算）里一枚以该会话用户身份运行的图标，但点一次菜单就失灵；
v1.0.3 修的就是这个失灵；v1.0.4 修的是"点了隐藏却没藏掉"和菜单里那项不该出现的
时候还挂着。右键菜单四件事，语义刻意分开：

| 菜单项 | 做什么 | 怎么回来 |
| --- | --- | --- |
| 打开配置 | 就地改服务器地址/连接密钥/控制密码，保存即热生效 | — |
| 停止远程控制 | 只关这条隧道，进程与服务都活着；控制端那侧设备行转成「重连中」 | 同一个菜单的「启动远程控制」；重启机器也自动恢复可控 |
| 隐藏托盘图标 | 收掉图标并记住这个选择——**全机**语义：这台机器上每个会话的图标一起退休，各自删各自的 | 双击桌面快捷方式，勾回「显示托盘图标」 |
| 退出（同时停止服务，下次开机自动回来） | 删图标、停服务、退出，**启动类型仍是自动** | 双击客户端把它以前台方式跑起来——菜单里那项「启用后台服务…」点下去就是真的启用（受限令牌下文案带「需管理员批准」，因为它要去要一次 UAC）——或等下次开机 |

「停止远程控制」期间 `sc query MyRemoteAgent` 照旧报 `RUNNING`——暂停的是隧道，不是服务，这就是它和开机自启的两码事。`agent.exe --service-state` 的 `proxies=` 会列出当前哪几个会话有图标。

**找不到图标时先点开右下角的 `^`。** Windows 11 会把第一次出现的托盘图标收进这个折叠区，直到用户自己把它拖出来，而这个偏好应用无权代用户设置。图标"没画出来"和"画了但被收起来"是两件事，前者看 `--service-state` 的 `proxies=`（没有你这个会话就是真没画）与 `%ProgramData%\MyRemote\tray-<会话>.log`（代理自己说连没连上宿主）。

## 系统要求

Windows 10/11 x64。不需要额外安装 VC 运行库（CRT 静态链接），被控端是单文件；控制端解压/安装后自带完整 Qt 运行时。

## 已知限制

- **没有代码签名**：下载后首次运行会吃 SmartScreen，点「更多信息 → 仍要运行」。
- **Ctrl+Alt+Del 无法注入**：若该机策略要求先按 Ctrl+Alt+Del 才出现登录框，把 `DisableCAD` 设为 1。
- 单显示器；多监视器选择未做。
- 一台机器只有一个服务名 `MyRemoteAgent`。装两份 agent（例如 `C:\MyRemote\Agent` 加另一个目录）不会各起一个服务，卸载任意一份都会把服务摘掉——实测过，装回来即可。
- 托盘代理以**该会话登录用户**身份运行，"暂停/退出/改配置"的权力属于坐在该会话里的人；管道 DACL 放行 SYSTEM、Administrators 与**交互式登录组**——也就是**在这台机器上交互登录过的任何用户**都能连上它（不是"该会话那个用户"）。因此这条管道只走图标层面的命令，`secret_key` 与控制密码从不推上管道，写配置的一定是持有真配置的宿主。把托盘当操作入口可以，当"这台机器正被谁控制"的权威凭据不行。
- 同一会话里的任何程序都能画出一枚一模一样的托盘图标，因此图标只是现场信息与操作入口。要知道现状，看 `--service-state` 的 `paused=` / `registered=` / `proxies=`，或控制端设备行。
- **托盘点一下可能像没反应**：宿主给每个托盘代理的读与写用的是同一个管道句柄，代理一旦长时间不读管道（例如卡在某个模态框里）而宿主恰好话多，这条连接上的命令就不会被处理，约 8 秒后按心跳超时断开重来——现场看到的是一枚图标闪一下复活、刚才那一下没生效。**这条不是 1.0.7 引入的**（v1.0.6 及更早同样有，2026-09-03 用三阶段读数确诊），已在计划中修；临时办法是再点一次，或从控制端那一侧停。
- 50+ 并发与自适应码率尚未压测。
